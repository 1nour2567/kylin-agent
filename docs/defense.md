# Kylin Agent 软件杯答辩手册

---

## 一、核心创新（开场 30 秒）

**一句话：AI Agent 管服务器很危险。我造了一堵不依赖 AI 的墙。**

别人教 AI "什么不能做"（prompt 约束），我们在 AI 外面造了一堵墙——所有安全决策全是确定性代码，LLM 不参与。

**七项架构创新：**

| # | 创新 | 一句话 |
|---|------|--------|
| 1 | 四层纵深防御（T0-T3） | LLM 输出只是"建议"，代码决定能不能做 |
| 2 | 态势引擎 | 根据 veto 事件动态调节安全等级，类似央行加息 |
| 3 | Agentic Loop | 多轮自主诊断，每轮都过 T0-T3，最多 3 轮 |
| 4 | SHA256 审计链 | 改一条全链断裂，密码学级不可抵赖 |
| 5 | 基线学习 + 3σ 异常检测 | AI 帮你看家，不只帮你执行 |
| 6 | v1.6.0 工程安全套件 | 熔断器 + 回滚 + 幂等 + 全链路 Trace |
| 7 | RCA 根因分析 | 5 阶段结构化推理链（Symptom→Hypothesis→Evidence→RootCause→Remediation） |

**验证数据：** 35 条越狱语料 0 穿透，16 次红队攻击 0 打穿，135 个单元测试 < 1 秒，麒麟 V11 真机部署通过。

## 二、答辩三段式叙事（3.5 分钟）

### 第一段：问题（30 秒）

LLM 会被注入、会幻觉、会输出危险命令。靠 prompt 约束不可靠——prompt 是软约束，今天对齐好的模型，明天换个 prompt 就能绕过。运维场景不容试错——一条 `rm -rf` 就是生产事故。

### 第二段：方案（2 分钟）

**LLM 负责想，代码负责决定能不能做。**

四层防御全部是确定性代码：
- T0（防注入）：13 条正则 + Unicode 规范化 + base64/hex 递归解码
- T1（风险评估）：从 Manifest 派生的确定性风险矩阵，LLM 不参与评分
- T2（约束验证）：双路径独立校验——结构化 tool+params 和原始命令正则同时生效
- T3（沙箱执行）：allowlist + sudo -n 降权 + auto/confirm/veto 三级粒度

**态势引擎**动态自调节：2 次 veto → restrictive（所有命令需确认），24h 无异常 → 自动回归 balanced，深夜 22-06 自动上锁。

**Agentic Loop**多轮自主诊断：执行命令 → 观察结果 → 推理下一步 → 每轮都过 T0-T3，最多 3 轮。像真正的运维工程师。

**SHA256 审计链**不可篡改：event₁ → hash → event₂ → hash(prev) → ...，改任意一条全链断裂。跨重启持久化。FOIA 端点支持审计回放。

### 第三段：验证（1 分钟）

35 条越狱语料 0 穿透。16 次红队攻击 0 打穿。135 个单元测试 < 1 秒全部通过。麒麟 V11 真机部署验证。前端实时展示 T0-T3 拦截效果 + 审计链 SHA256 完整性校验。所有指标可量化。

## 四、常见评委问题

### 安全类

**Q: 如果 LLM 被攻击，输出了恶意命令，能拦截吗？**
> 能。T2 约束层不信任 LLM 的输出——它独立验证每个命令。LLM 输出 `rm -rf /`，T1 评分 10 分，T3 veto 级永不可执行。LLM 是观察者，不是决策者。

**Q: 和 prompt 约束有什么区别？**
> Prompt 是软约束——LLM 可能被越狱绕过。我们的 T0-T3 是确定性代码——正则匹配、字典查找、文件路径检查——不经过 LLM。攻击者即使完全控制了 LLM 也无法绕过。

**Q: 误拦了正常操作怎么办？**
> 每个拦截都带一个可操作的建议（alternative）。"你要删 `/var/log/mysql/slow.log`" → "建议用 logrotate 轮转而非直接删除"。宁可多确认一次，不能漏放一个。

### 创新类

**Q: 和现有运维工具（蓝鲸、Ansible）有什么区别？**
> 蓝鲸和 Ansible 执行预定义脚本——运维人员需事先写流程。Kylin 执行自然语言指令——用户说"nginx 不可用，帮我排查"，Agent 自主规划诊断步骤。且每个步骤都经过四层安全校验。

**Q: 创新点到底是什么？**
> 两个核心创新：(1) Constraint Architecture——LLM 想，代码定，四层约束全部不依赖 LLM；(2) Agentic Loop 多轮自主推理——每轮 Reason→Validate→Execute→Observe，结果反馈给下一轮。

### 技术类

**Q: 系统响应时间多少？**
> 核心延迟在 LLM 推理（DeepSeek API 约 1-3 秒）。T0-T3 安全管线 < 5ms（全部确定性计算）。Agentic Loop 最多 3 轮，总耗时 < 15 秒。135 个单元测试全部 < 1 秒。

**Q: 怎么处理并发？**
> 当前单用户设计——面向单台服务器运维场景。多用户在架构上可通过 SessionStore 水平扩展支持，是目前已知限制。

**Q: 能和别的系统对接吗？**
> 已支持 MCP 协议（标准化 Agent 工具接口）。任何支持 MCP 的系统可直接调用 Kylin 工具。同时提供 REST API。

### 国产化类

**Q: 为什么选择麒麟？**
> 麒麟是国产 OS 主力——军队、政府、金融都在推。但运维人员少、技术积累薄。Kylin 让不熟悉命令行的管理员通过自然语言完成运维。降低国产 OS 使用门槛。

**Q: 在 LoongArch 上跑过吗？**
> 代码纯 Python 实现——理论上跨架构。x86_64 麒麟 V11 上已完成全部测试和部署验证。LoongArch 上只需重新安装 Python 依赖。

### 知识沉淀类

**Q: 系统怎么积累知识？今天拦的攻击，明天再来能记住吗？**
> 四层：(1) 规则库沉淀——改一行 YAML，重启即全局生效；(2) 基线学习——30 天滚动基线，3σ 异常检测；(3) 态势记忆——restrictive 持续 24h；(4) 未来方向——审计链积累 → LLM 离线分析 → 自动生成规则草案。

### 答辩技巧

**被指出缺点：** 先承认→解释权衡→给方案。"是的，这块目前确实 [缺点]。原因是 [技术权衡]。后续通过 [具体方案] 改善。"

**被问不会的问题：** "这是一个很好的问题。目前设计是 [简述]，[评委指出的方向] 确实是我们后续需要加强的。"

**自由发挥时：** "我简单概括三个核心创新：第一，Constraint Architecture——LLM 想，代码定。第二，Agentic Loop 多轮自主诊断。第三，SHA256 审计链保证了操作的不可抵赖性。"
